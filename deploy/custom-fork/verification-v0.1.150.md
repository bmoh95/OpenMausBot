# v0.1.150 리베이스 검증

2026-11-09 UTC에 `custom/production`의 기존 커스텀 커밋 14개를 공식
`v0.1.150` (`5491874882378603aef2536790650a192e63d56d`) 위로 리베이스했다.
후보 브랜치는 `update/v0.1.150-20261109`다.

## 유지한 수정과 충돌 해결

14개 중 12개는 같은 패치로 유지됐다. 나머지 2개는 시스템 프롬프트와 관련
테스트의 충돌을 해결했다. `range-diff`로 커밋별 대응 관계를 확인했다.

- 공식 버전의 모든 봇 공통 규칙을 유지하고, reply style 기본값보다 뒤에서
  주입한다. SOUL과 부서 지침을 주입하는 기존 경로도 유지한다.
- 일반 호스트 명령은 foreground에서 실제 종료 코드와 출력을 확인하는
  0.1.150 지침을 유지한다. Local VM 안에서는 VM이 명령 호출 이후에도
  유지되므로 긴 작업을 VM 내부에서 분리 실행할 수 있다.
- 짧은 확인·실패 직후 작업을 끝내지 않고, 제한된 재확인·복구와 독립 작업을
  계속한다는 커스텀 지침을 유지한다. 자동 대기를 설정할 수 없는 위임 작업은
  해당 턴에서 수행하도록 하는 공식 제한도 유지한다.
- 계정 사용량 제한 시 백업 모델 전환, Codex 그룹 세션 연속성, 스킬 인덱스,
  MCP 재시작, 공유 폴더 및 관리자 VM 정책을 유지한다.

검증 중 기존 Goal 커스텀 코드의 결함도 수정했다. 한 명짜리 그룹에서
코디네이터가 자신에게 작업을 위임한 뒤에는 별도 검증자를 선택하지 못할 수
있었다. 다른 검증자가 없으면 같은 봇이 별도의 읽기 전용 검증 턴을 수행한다.
완료 검증을 생략하거나 실패한 검증을 통과로 취급하지 않는다.

Goal 통합 시험은 완료 검증 턴·잘못된 판정 재검토·65턴까지의 확장에 맞췄다.
긴 대화에서는 tail 페이지 밖으로 밀린 목표 카드를 ID/요청 앵커로 조회한다.
시험은 격리된 데이터·포트와 scripted fake engine으로 실행했다.

## 검증 결과

- 관련 회귀 검사와 통합 검사 **500개 통과**, 실패 0개. 전체 프로젝트의 모든
  플랫폼·모든 시험을 실행했다는 의미는 아니다.
- 사용량 제한/모델 전환 통합 검사 4개, 팀 Goal 통합 검사 12개, 개인 Goal 통합
  검사 7개, Goal 단위 검사 21개와 시스템 프롬프트 preview 검사를 포함한다.
- `pnpm lint`, `pnpm build:server` 통과.
- 공식 control surface로 별도 fixture를 실행하고 Bot 생성 → 메시지 전송 →
  `settled` 상태 → 응답 조회를 확인했다.
- 공식 0.1.150 frontend + 커스텀 server bundle의 ARM64 Docker 이미지 빌드 성공.
  별도 데이터 볼륨, 운영 인증 및 Docker socket 없이 실행한 후보 컨테이너에서
  `/api/health`, `/`, 연결된 JS/CSS 자산이 HTTP 200으로 응답했다.
- 후보 번들에서 관리자 VM 지침, 작업 계속 수행 지침, 공통 규칙 주입과
  conversational 완성도 지침을 확인했다.

## 이미지와 배포 상태

공식 multiarchitecture 이미지:

```text
ghcr.io/milind-soni/openmausbot:v0.1.150@sha256:e16b592770600f5503586f6e8a9bdfe4c06658d5aed73b4fc7c978ed6e816edf
```

서버에 준비한 후보:

```text
openmausbot-codex:0.1.150-candidate
sha256:09022509560f9b9724cad811aad41970efb8474b60b613d3406832a9a3837340
```

실제 이미지 ID는 배포 시 `docker image inspect`로 다시 대조한다. build context는
`~/openmausbot-candidate-150`이며, server bundle을 만든 소스 커밋은 그 디렉터리의
`SOURCE-REVISION`에 기록한다. 이후 시험·문서만 바뀐 커밋과 구분한다.

이 후보를 준비하는 동안 운영 서버는 0.1.149 기반으로 계속 실행했다.
`custom/production`과 기존 Android `main`은 이 후보로 이동하지 않았다.
실제 계정 로그인·사용량, 기존 데이터 migration, 실시간 화면 제어와 외부 MCP의
운영 0.1.150 검증은 배포 과정에서 별도로 확인해야 한다.
